# MIearn Piper Lessac High 音频升级设计

## 目标

第一阶段在不修改学习页面、Room 数据、学习队列和运行时播放接口的前提下，将内置英语音频升级为 Piper `en_US-lessac-high`、40 kbps 单声道 Ogg/Opus，并通过可审计的专业发音覆盖词典修正制造业术语、缩写及特殊表达。

首阶段只生成 50 条 A/B 试听样本，不覆盖现有音频。用户确认声音与专业发音后，另行执行全量生成。

第二阶段在音频试听交付后新增全屏单词详情页。用户点击学习卡中的普通英文或已切分的紫色英文片段即可进入详情页，查看并播放该表达的发音和音标。第二阶段不得改变学习判定、队列、SM-2 或自动发音行为。

## 方案选择

采用单一 Piper High 音色方案：

- 继续使用构建期离线合成，APP 只打包生成后的 Ogg 文件。
- 不在 APK 中内置 Piper 模型。
- 不在本阶段引入 Kokoro、云端 TTS 或应用内音色切换。
- 运行时继续优先播放内置音频，缺失时沿用现有 Android TTS 回退。

这样能保持单词与句子音色一致，并将改动限制在内容构建流水线。

## 试听样本

从 `words_v1.json` 自动、确定性地选择 50 条，覆盖：

- 普通单词和短语。
- 含多个英文表达的词条。
- 完整句子。
- 机械、电气、客户评审、会议口语和商务句子五类内容。
- 缩写、符号、连字符及容易误读的专业术语。

以下内容为必测项：`fixture`、`jig`、`GD&T`、`CMM`、`PLC`、`mylar`。若某项不是独立词条，则选择包含它的词条；若词库确实不存在，则在报告中明确记录，不伪造词条。

样本选择规则和随机种子固定，使重复运行得到相同清单。

## A/B 产物

每个样本提供两套音频：

- A：当前 Lessac Medium 32 kbps 基线，可直接复用现有资产。
- B：Lessac High 40 kbps 候选音频。

试听产物写入独立的、可清理目录，不写入 `app/src/main/assets/audio`，也不影响 APK 构建。目录包含：

- A/B 音频文件。
- 按词条排列的试听清单。
- 英文原文、实际朗读文本、分类、词条 ID 和覆盖规则命中信息。
- 校验结果与文件哈希。

试听清单不隐藏 A/B 身份，因为本阶段目标是工程验收和发音核对，不进行正式双盲实验。

## 专业发音覆盖词典

新增版本控制的 `pronunciation_overrides.json`，由生成脚本读取。覆盖规则以稳定词条 ID 为最高优先级，并允许按精确英文片段配置。每条规则记录：

- 原始显示文本。
- 实际朗读文本。
- 可选说明。
- 规则类型：缩写逐字母、符号展开、术语修正或专名修正。

覆盖只改变合成输入，不改变 APP 中显示的英文、音标、中文或搜索内容。多表达词条逐片段应用覆盖，再生成独立片段音频和带 500 ms 间隔的完整音频。

首批至少覆盖 `GD&T`、`CMM`、`PLC`；`fixture`、`jig`、`mylar` 先使用模型默认读法，只有试听发现错误时才增加显式覆盖，避免无依据的音素硬编码。

## 编码与音频规范

候选音频统一为：

- Piper `en_US-lessac-high`。
- 单声道。
- Ogg/Opus。
- 40 kbps。
- Opus `application=audio`。
- 输出采样率使用 Opus 支持的 48 kHz，由 Piper 的 22.05 kHz 源音频高质量重采样。
- 多片段完整音频在片段之间插入精确 500 ms 数字静音。
- 独立片段不添加额外静音。
- 不人为加入背景音乐、混响或音效。

生成过程保持确定性，并继续规范化容器元数据，避免相同输入产生无意义的哈希变化。

## 校验与失败策略

试听生成完成前必须验证：

- 样本数量恰好为 50。
- 必测项存在性检查已执行。
- A/B 清单、文件与词条 ID 一一对应。
- 所有音频可解码、时长大于零且不是静音。
- 声道、编码、目标码率与采样率符合规范。
- 多表达完整音频包含规定的 500 ms 间隔。
- 覆盖词典没有重复键、空朗读文本或无法匹配的规则。
- 哈希及实际文件字节数与报告一致。

任一强制校验失败时中止任务，不覆盖现有资产，也不输出“通过”报告。

## 用户验收

用户重点试听并判断：

- 美式女声音色是否比当前版本清晰自然。
- 单词首尾是否完整、响度是否一致。
- 制造业术语与缩写是否准确。
- 多表达之间的停顿是否自然。
- 完整句子是否存在异常加速、吞音或错误重音。

只有用户明确确认 B 方案后，才进入全量重生成设计与实施。试听通过不自动修改版本号、生成 APK 或发布 GitHub Release。

## 第二阶段：全屏单词详情页

详情页采用已确认的全屏方案，不使用底部面板。入口覆盖第一遍浏览卡、复习卡和错题强化卡中由 `EnglishVariants` 展示的英文内容：

- 单一英文表达点击后打开该词条详情。
- 紫色分段表达点击后携带词条 ID 与片段索引，详情页聚焦被点击的片段。
- 点击行为与原有播放操作分离；发音按钮继续只负责播放，点击文字才负责导航。
- 页面支持系统返回手势和顶部返回按钮，返回后保留学习会话与当前卡片。

详情页保持克制，只显示当前英文表达、音标、发音按钮、中文释义、收藏按钮，以及词条已有的双语例句。

片段音标按以下确定性规则显示：

1. 音标能按现有分隔符切分，且数量与英文片段数量一致时，显示同索引音标。
2. 无法可靠一一对应时，显示词条完整音标并标注为整条音标。
3. 音标为空时不显示占位音标，也不通过模型猜测或生成。

片段详情的发音按钮调用 `playVariant(word, index)`；单一表达调用 `play(word)`。离开详情页时停止本页主动触发的发音，避免退出后继续播放。页面复用现有主题、词条数据和收藏逻辑，不增加 Room 字段或第三方依赖。
## 体积与许可

Piper High 模型只保存在仓库外的构建缓存中，不提交 Git，也不进入 APK。项目第三方声明记录模型名称、版本、哈希、来源、工具许可及数据集许可链接。

40 kbps 相比当前 32 kbps 会增加音频资产体积；全量阶段仍需执行 APK 体积门禁。试听阶段不改变 APK 大小。

## 测试范围

- 单元测试覆盖样本选择的确定性、覆盖规则优先级、分段覆盖与非法词典拒绝。
- 流水线测试覆盖 40 kbps 编码参数、文件命名、清单、哈希和 500 ms 静音。
- 回归检查确认试听任务没有改动 APP 正式音频目录、Room 或 Kotlin 运行时代码。
- 详情页单元测试覆盖片段音标同序匹配、完整音标回退与空音标。
- Compose 测试覆盖普通英文和紫色片段导航、片段独立发音、收藏、系统返回及会话保持。
- 详情页完成后执行 `assembleDebug`、`test` 和 `lint`，并回归学习队列、自动发音与正误反馈。

## 非目标

- 不生成全部 2,704 条正式音频。
- 不覆盖当前 Lessac Medium 音频。
- 第一阶段不修改学习卡片、发音按钮或 TTS 回退行为；第二阶段只增加英文文字的详情导航。
- 不增加网络权限。
- 不内置 TTS 模型。
- 不生成 Release APK，不修改版本号，不发布 GitHub。
